1. Why the Current Approach Failed

❌ OLD: PDF Primitive Analysis

  • 33,000+ lines, curves, text primitives
  • Complex geometric intersection logic
  • Template-based room centers (not actual positions)
  • 8 scripts, 2,000+ lines of code
  • 10+ debug iterations per drawing
  • 60-70% position accuracy
  • Building geometry doesn't match PDF

✅ NEW: Vision API Text Extraction

  • ~200 text detections with positions
  • Simple regex pattern matching
  • Actual symbol positions from drawing
  • 2 scripts, ~500 lines of code
  • 2-3 iterations max
  • 95%+ position accuracy (proven)
  • Objects placed where symbols appear
Root Cause of Failure: The old pipeline tried to mathematically derive object positions from geometric primitives. This created a "template" of where objects should be, not where they actually appear on the drawing. Vision API extracts where labels actually are.

1
PDF to PNG Conversion
Convert each page to high-resolution PNG
import fitz  # PyMuPDF
from pathlib import Path

def pdf_to_png(pdf_path: str, output_dir: str, dpi: int = 300):
    """
    Convert PDF pages to PNG images for Vision API processing.
    
    Args:
        pdf_path: Path to input PDF
        output_dir: Directory for PNG outputs
        dpi: Resolution (300 recommended for architectural drawings)
    """
    doc = fitz.open(pdf_path)
    output_path = Path(output_dir)
    output_path.mkdir(exist_ok=True)
    
    for page_num in range(len(doc)):
        page = doc[page_num]
        
        # High resolution for text clarity
        mat = fitz.Matrix(dpi/72, dpi/72)
        pix = page.get_pixmap(matrix=mat)
        
        output_file = output_path / f"page{page_num + 1}.png"
        pix.save(str(output_file))
        
        print(f"Page {page_num + 1}: {pix.width}×{pix.height}px")
    
    doc.close()
    return list(output_path.glob("*.png"))

Vision API Extraction
Extract all text with pixel positions
from google.cloud import vision
from PIL import Image
import json
import re

def extract_from_image(image_path: str) -> dict:
    """
    Extract text + positions using Google Vision API.
    Same proven approach from survey pipeline.
    """
    client = vision.ImageAnnotatorClient()
    
    with open(image_path, 'rb') as f:
        content = f.read()
    
    image = vision.Image(content=content)
    response = client.document_text_detection(image=image)
    
    # CRITICAL: Get dimensions from PIL, not API bounds
    img = Image.open(image_path)
    width, height = img.size
    
    extractions = []
    
    for text in response.text_annotations[1:]:  # Skip first (full text)
        vertices = text.bounding_poly.vertices
        x = sum(v.x for v in vertices) / 4
        y = sum(v.y for v in vertices) / 4
        
        extractions.append({
            "text": text.description.strip(),
            "x": round(x, 1),
            "y": round(y, 1),
            "bbox": {
                "x1": vertices[0].x,
                "y1": vertices[0].y,
                "x2": vertices[2].x,
                "y2": vertices[2].y
            }
        })
    
    return {
        "metadata": {
            "source": image_path,
            "image_dimensions": {"width": width, "height": height},
            "extraction_count": len(extractions)
        },
        "text_items": extractions
    }
Key Lesson Applied: Always use PIL.Image.open() for dimensions, never Vision API text bounds. This bug caused 336px error in survey pipeline.

Floor Plan Parser
Categorize extractions by pattern
import re

def parse_floor_plan(extraction: dict) -> dict:
    """
    Parse Vision API extraction into categorized objects.
    """
    patterns = {
        "doors":       re.compile(r'^D[1-9]$'),
        "windows":     re.compile(r'^W[1-9]$'),
        "grid_cols":   re.compile(r'^[A-E]$'),
        "grid_rows":   re.compile(r'^[1-5]$'),
        "rooms":       re.compile(r'^(BILIK|DAPUR|TANDAS|RUANG|CORRIDOR)', re.I),
        "fan_points":  re.compile(r'^FP[1-9]?$'),
        "switches":    re.compile(r'^SWS$'),
        "gutters":     re.compile(r'^G[1-9][0-9]?$'),
    }
    
    result = {key: [] for key in patterns}
    result["metadata"] = extraction["metadata"]
    
    for item in extraction["text_items"]:
        text = item["text"]
        
        for category, pattern in patterns.items():
            if pattern.match(text):
                result[category].append({
                    "label": text,
                    "px": item["x"],
                    "py": item["y"]
                })
                break
    
    # Summary
    print(f"Doors: {len(result['doors'])}")
    print(f"Windows: {len(result['windows'])}")
    print(f"Grid columns: {len(result['grid_cols'])}")
    print(f"Grid rows: {len(result['grid_rows'])}")
    
    return result

Scale Calibration from Grid
Calculate pixel-to-meter scale using grid labels
def calibrate_scale(parsed: dict, building_config: dict) -> dict:
    """
    Calculate scale using grid labels (like chainage in survey pipeline).
    
    Args:
        parsed: Output from parse_floor_plan()
        building_config: Manual input with real dimensions
    
    Returns:
        Calibration data with scale factors
    """
    # Find grid extremes
    cols = sorted(parsed["grid_cols"], key=lambda x: x["px"])
    rows = sorted(parsed["grid_rows"], key=lambda x: x["py"])
    
    if len(cols) < 2 or len(rows) < 2:
        raise ValueError("Need at least 2 grid labels per axis")
    
    # Pixel spans
    px_width = cols[-1]["px"] - cols[0]["px"]
    px_height = rows[-1]["py"] - rows[0]["py"]
    
    # Real dimensions from config
    real_width = building_config["grid_width_m"]   # 11.2m
    real_height = building_config["grid_height_m"]  # 8.5m
    
    # Calculate scales
    scale_x = real_width / px_width
    scale_y = real_height / px_height
    
    # Origin (Grid A, Row 1 position)
    origin_px = cols[0]["px"]
    origin_py = rows[0]["py"]
    
    print(f"Scale X: {scale_x:.6f} m/px")
    print(f"Scale Y: {scale_y:.6f} m/px")
    print(f"Origin: ({origin_px}, {origin_py}) px")
    
    return {
        "scale_x": scale_x,
        "scale_y": scale_y,
        "origin_px": origin_px,
        "origin_py": origin_py,
        "image_height": parsed["metadata"]["image_dimensions"]["height"]
    }

Coordinate Transform
Convert pixel positions to world coordinates
def pixel_to_world(px: float, py: float, calibration: dict) -> tuple:
    """
    Convert pixel coordinates to world coordinates.
    
    CRITICAL: Y-axis is flipped (image Y=0 at top, Blender Y=0 at bottom)
    """
    # Offset from origin
    dx = px - calibration["origin_px"]
    dy = py - calibration["origin_py"]
    
    # Scale to meters
    x = dx * calibration["scale_x"]
    
    # FLIP Y-AXIS (critical!)
    y = -dy * calibration["scale_y"]  # Negative because image Y increases downward
    
    return (round(x, 3), round(y, 3))


def generate_placements(parsed: dict, calibration: dict, object_map: dict) -> list:
    """
    Generate 3D placements from parsed floor plan.
    
    Args:
        parsed: Categorized extractions
        calibration: Scale and origin data
        object_map: Door/window code to library object mapping
    """
    placements = []
    
    # Doors
    for door in parsed["doors"]:
        x, y = pixel_to_world(door["px"], door["py"], calibration)
        
        placements.append({
            "name": f"{door['label']}_x{int(x*10)}_y{int(y*10)}",
            "object_type": object_map["doors"][door["label"]],
            "position": [x, y, 0.0],
            "category": "door",
            "source_label": door["label"]
        })
    
    # Windows (same pattern)
    for window in parsed["windows"]:
        x, y = pixel_to_world(window["px"], window["py"], calibration)
        
        placements.append({
            "name": f"{window['label']}_x{int(x*10)}_y{int(y*10)}",
            "object_type": object_map["windows"][window["label"]],
            "position": [x, y, 1.0],  # Windows at sill height
            "category": "window",
            "source_label": window["label"]
        })
    
    return placements

Blender Import (Critical Fix)
Apply proven survey pipeline fixes
# ═══════════════════════════════════════════════════════════════════════════════
# CRITICAL BLENDER FIX - LEARNED FROM SURVEY PIPELINE
# ═══════════════════════════════════════════════════════════════════════════════
#
# Blender's empty_display_size=1.0 normalizes image to longest dimension.
# Setting scale=(width, height) applies aspect ratio TWICE → Y compressed!
#
# WRONG:  empty.scale = (world_width, world_height, 1.0)
# RIGHT:  empty.scale = (world_width, world_width, 1.0)  # Use WIDTH for BOTH
#
# ═══════════════════════════════════════════════════════════════════════════════

import bpy

def create_reference_image(image_path: str, world_width: float, z_height: float = 0.0):
    """
    Create floor plan reference image with CORRECT scaling.
    """
    bpy.ops.object.empty_add(type='IMAGE', location=(0, 0, z_height))
    empty = bpy.context.active_object
    empty.name = "Floor_Plan_Reference"
    
    img = bpy.data.images.load(image_path)
    empty.data = img
    
    # CRITICAL SETTINGS
    empty.empty_display_size = 1.0
    empty.empty_image_offset = (0, 0)  # Bottom-left anchor, NOT (-0.5, -0.5)
    
    # CRITICAL: Use world_width for BOTH X and Y!
    # Blender's internal aspect ratio handles the rest.
    empty.scale = (world_width, world_width, 1.0)
    
    return empty
DO NOT "FIX" THIS! Using (world_width, world_height, 1.0) will break Y alignment. This bug took hours to diagnose in the survey pipeline. Blender handles aspect ratio internally.

9. Summary: Key Principles

✅ DO

  • Extract text at actual positions (Vision API)
  • Get image dimensions from PIL
  • Use grid labels for scale calibration
  • Apply (width, width, 1.0) for Blender image scale
  • Cache JSON, iterate transforms without re-calling API
  • Validate counts match schedule

❌ DON'T

  • Analyze 33K geometric primitives
  • Use template-based room centers
  • Calculate positions mathematically
  • Use Vision API bounds for image dimensions
  • Apply (width, height, 1.0) for Blender scale
  • Re-run API when only transform changes
